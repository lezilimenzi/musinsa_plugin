# MUSINSA Need-aware Look-first Agent

MD/서비스 기획자가 홈·추천판·기획전에 사용할 대표 키워드와 전신 코디 슬롯 후보를 만드는 로컬 배치형 MVP다.
공개 웹 트렌드를 검색해 **자유서술 신호 → 창발 테마 → LLM 제로샷 룩 랭킹**으로 슬롯을 구성한다.
통제어휘 태그 매칭은 쓰지 않는다.

## 플러그인 작동 방식

이 플러그인은 홈 화면에 "어떤 코디를 왜 노출할지"를 근거와 함께 제안하는 로컬 배치 파이프라인이다.

**작동 절차**
1. 웹 검색(OpenAI web_search)으로 트렌드·이벤트·날씨 근거를 수집한다.
2. LLM이 근거에서 자유서술 신호(대표 키워드·설명·출처 ID)를 추출한다.
3. 신호를 의미별로 묶어 창발 테마 3~6개를 만든다(사전 카테고리 없이 데이터에서 도출).
4. 테마마다 LLM이 전신 코디 룩을 제로샷으로 랭킹한다.
5. 모든 (테마·룩) 쌍을 적합도(fit_score)로 전역 정렬해 상위부터 슬롯에 배정한다.

**지식·판단 기준**
지식은 사전 태그 사전이 아니라 매 실행의 웹 검색과 브랜드 카탈로그(브랜드 전문성·아이덴티티)에서 가져온다. 판단은 LLM 적합도로 하되, 브랜드 전문성이 테마와 맞으면 가점한다(예: 수영복 전문 브랜드 ↔ 물놀이 테마). 하드 기준으로 전신 코디만, 슬롯마다 근거 출처 필수, 룩 중복 금지, 매출·전환 등 근거 없는 주장 금지를 강제하고, `min_fit_score` 미만 저품질 매칭은 버린다.

**정보 부족·실패 시**
검색 실패 카테고리는 재시도 후 건너뛰고, 전부 실패하면 결과를 위조하지 않고 중단한다. LLM 출력은 스키마·근거 부분집합 검증을 통과한 것만 쓴다. 맞는 룩이 부족하면 슬롯을 억지로 채우지 않고 적게 만들며 커버리지 갭을 리포트에 남긴다(검증은 통과). 테마 균형은 강제하지 않아 트렌드가 특정 테마에 쏠릴 수 있다.

## AI 활용

**AI에게 맡긴 것**: 기획·계획 문서 초안, 코드 작성, 에러 진단, 문서 정리. 실행 중에도 웹 검색·패션 신호 추출·테마 묶기·코디 적합도 채점을 모두 AI가 한다.

**사람이 판단한 것**: 구조·정책 결정. 사람이 정한 태그(예: rock_chic)로 '같은 태그면 연결'하던 매칭을 버리고 AI가 적합도를 직접 판단하게 바꿨다. 카테고리를 고정하지 않고 AI가 데이터에서 테마를 만들게 했고, 오프라인 연습 모드를 없애 실제 검색으로만 돌렸다. 품질 하한선(적합도 0.6 미만 탈락)을 정하고, 가짜 검수 데이터는 지웠으며, 코드 작성 전 계획서를 승인받았다.

**막힌 지점·해결**: 검색이 멈춘 원인은 (1) AI가 검색 없이 자기 지식으로 답함, (2) 한국어 신호와 영어 태그가 글자가 안 맞아 매칭 0. → 검색을 강제하니 출처가 확보돼 (1)이 풀렸고, '글자 맞추기'를 버리고 AI가 뜻으로 적합도를 판단하니 언어·철자가 달라도 매칭돼 (2)가 풀렸다. 또 예전엔 테마가 순서대로 남은 룩을 집어, 한 룩이 잘 맞는 테마(0.70)보다 순서가 먼저 온 테마(0.08)에 끌려가 낭비됐다. → 모든 조합을 점수로 한 번에 비교해 배정하니 각 룩이 가장 잘 맞는 테마로 갔다.

**거부한 AI 제안**: ①여러 기준(트렌드 일치·날씨/이벤트·연결 상품·라벨 신뢰도·클릭·다양성)을 한 점수로 뭉쳐 순위만 매기자 → 왜 그 룩이 상위인지 설명하기 어려워 거부. ②검색 결과가 없는 주제는 바로 빼자 → 제대로 안 찾고 빼는 건 부적절해 검색 강제·재시도했고, 그래도 없으면 그 주제만 빼고, 전부 실패하면 지어내지 않고 멈춘다.

## 슬롯 구성

- 카테고리는 사전 고정이 아니라 신호에서 **창발한 테마 3~6개**다.
- 룩 랭킹에 **브랜드 전문성**을 반영한다 — 각 룩의 브랜드와 `brand_catalog.csv`의 전문 분야·아이덴티티를 LLM에 주고, 브랜드 전문성이 테마와 맞으면(예: 수영복 전문 브랜드 ↔ 물놀이 테마) 적합도를 더 높인다.
- 모든 (테마,룩) 쌍을 fit_score로 **전역 배정**하고 `min_fit_score` 미만은 버린다. 중복 없이 `target_slots`(기본 10)까지, 테마당 최대 `per_theme_cap`.
- 룩 인벤토리가 부족하면 채운 만큼만 만들고 커버리지 갭을 리포트에 기록한다.
- 채워진 모든 슬롯은 대표 키워드, 검증된 전신 코디, 연결 상품, 근거 source ID를 포함한다.

설정은 `inputs/home_context_config.yaml`의 `target_slots`, `per_theme_cap`, `theme_count`로 조정한다.
